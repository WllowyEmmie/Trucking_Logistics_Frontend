Surface 3 · desktop, one shift

Dispatcher console

Every frame is live. Click deliveries, trucks, markers, chips and counts; expand a row with its chevron; ask a question; approve a proposal. Markers glide between pings at constant speed over each 10 s interval, so the shown position trails the latest report by at most one ping instead of jumping.

1Populated default

A delivery selected and expanded in place: ordered stops with filled dots for done, the event timeline, route and truck lit on the map. Exceptions sit in a compact table in the header; the agent-raised row carries the violet Agent marker instead of Rule.

2Assign flow, inline

Pending delivery expanded. Available trucks are listed by distance to pickup and all enlarge on the map; hovering or focusing a candidate draws a dashed line to the pickup. Assign changes the pill in place and logs the event. No modal, so the map stays in view. Try KF-25 first: it returns a 409 because another dispatcher just took it. The server's message is shown word for word and the list refreshes.

3Agent: proposal and inline answer

The proposals pane is opened with one proposal: what it would do, why, the before and after, and Approve / Reject 16px apart. The ask box has answered above the list; each answer row selects that delivery. No chat thread, no history of turns.

4Empty: start of shift

No deliveries yet. Counts read zero, the exception table says nothing needs attention, and the proposals pane is opened to show its empty state, which is how it will look most of the time. New delivery opens an inline form above the list, never a modal. Creating drops the delivery in as Pending, selected and expanded, so the assign panel is right there.

5Zoomed to 200%

A 1440px screen at 200% gives a 720px CSS viewport. Panes become tabs, the exception table reflows into stacked rows with the same fields, and the delivery list keeps every value; nothing clips or truncates. Shown at 2× scale.

6Night shift, dark theme

Same tokens under the .dark class; every status pair keeps its contrast. The map stays on light tiles, because markers are tuned against OSM tiles. A dark tile set would need its own marker check.

7Right-to-left

dir="rtl" on the root. Panes, chips and row layouts mirror through logical properties, so the delivery list sits on the right and the proposals rail on the left. The map is not mirrored, because geography doesn't flip. The strings are left in English here so the layout change is easy to see.
